# UX/UI-исследование тренажёра «Архитектура ПО» — октябрь 2026

**Статус:** готов отчёт по сценариям и эвристикам — **[REPORT-walkthrough.md](REPORT-walkthrough.md)**: 25 проблем с серьёзностью, топ-10 рекомендаций, что сохранить. Отчёт по замерам (`REPORT-metrics.md`) ещё дописывается; сырые данные — в `data/`.

## Что исследуем и как

Сайт: https://andreypol1991.github.io/arch-trainer/ — 51 раздел, один HTML-файл.

1. **Замеры** — `data/`:
   - производительность в Chrome через DevTools Protocol: ноутбук и «средний телефон на 4G, процессор ×4»;
   - размеры и объём текста по разделам;
   - доступность по правилам axe-core (WCAG 2.2 AA) по каждой вкладке в обеих темах;
   - горизонтальное переполнение на ширине 390 px.
2. **Сценарии ученика и 10 эвристик Нильсена** — `shots/`, 40 снимков. Сценарии:
   - первый визит с телефона и с ноутбука;
   - возвращение через неделю;
   - поиск темы;
   - прохождение нового и старого раздела;
   - сдача кода в «Практике»;
   - тёмная тема;
   - встраивание в iframe;
   - игры и каталог.

## Что уже видно по снимкам (предварительно, ждёт отчёта)

- **Возвращение:**
  - страница открывается на разделе 0, а не там, где ученик остановился (`10_return_lands_on_section0.png`);
  - в меню нет отметок «пройдено» (`11_…`);
  - счётчик заданий в старых разделах после перезагрузки показывает 0, хотя баллы сохранены (`12_…`).
- **Поиск:** ищет только по названиям разделов — «идемпотентность» не находит ничего (`15_…`).
- **Внутри длинного раздела** нет признака, где ты: карта глав только наверху (`20_…`).
- **Телефон:** горизонтальное переполнение в EXPLAIN (`40_…`).
- **Разная подача:** старые разделы (саги, согласованность) — набор карточек, новые — история с картой глав (`25_…`, `27_…` против `17_…`, `19_…`).
- **Хорошо работает:**
  - живые модели — репликация, Raft (`21_…`, `22_…`);
  - меню с группами и закреплённая панель на широком экране;
  - генерация кода в «Практике»;
  - тёмная тема.
